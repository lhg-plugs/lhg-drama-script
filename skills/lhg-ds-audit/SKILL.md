# lhg-ds-audit：剧本自检（机器先查，人再查）

> 目标：剧本交付前，用**确定性脚本 + 人工评审清单**两道网，把低级错误和结构硬伤拦下来。
> 核心纪律：**blocker 清零才算做完**；为清零而改规则、删标记，算作弊。

## 1. 何时使用

- 单集剧本写完、准备交付/定稿 → 全流程
- 大纲写完想快速验证结构 → 只跑第 2 节的"大纲速查"
- 审计脚本报 warning 拿不准要不要修 → 按第 4 节定级标准判定

## 2. 输入与输出

**输入**：剧本文件目录（含一个或多个 `*.md` 剧本文件，格式见 lhg-ds-episode 第 7 节）。

**输出**：

1. 审计脚本报告（`drama_audit.py` 的 JSON/text 输出）： findings 列表，每条含 rule_id / severity / file / line / detail
2. 人工评审结论：按第 5 节清单逐条给出 通过/不通过 + 改写建议
3. 定稿判定：blocker=0 且人工清单全过 → 可定稿；否则列出必修项

## 3. 审计脚本用法

```bash
# 查一个目录下所有剧本文件
python3 scripts/audit/drama_audit.py --target ./scripts/ --format text

# 只看 blocker（定稿门禁）
python3 scripts/audit/drama_audit.py --target ./scripts/ --fail-on blocker

# JSON 输出（供二次处理）
python3 scripts/audit/drama_audit.py --target ./scripts/ --format json
```

**三级发现定级**：

| 级别 | 含义 | 处置 | exit code |
|---|---|---|---|
| blocker | 结构硬伤（反转不足 3、无钩子、人物未登记） | 必须修，不许豁免 | 2 |
| warning | 可能的问题（时长超标、台词过长、场次过多） | 修，或写一句话豁免理由 | 1（仅 warning 时） |
| nit | 格式小毛病（标记编号不连续、称呼建议统一） | 顺手修 | 0 |

`--fail-on` 语义：`blocker`（默认）= 有 blocker 才非零退出；`warning` = 有 warning 及以上非零；`nit` = 任何发现都非零。

**豁免流程**（只适用于 warning/nit）：在剧本文件对应行末加 `<!-- 豁免：理由 -->`，审计脚本会识别并降级为备注；blocker 不接受豁免。豁免理由必须具体（"第 5 场是打戏，时长单独核算"✓；"感觉没问题"✗）。

## 4. 规则速查（审计脚本覆盖项）

| 类别 | 规则示例 | 级别 |
|---|---|---|
| 反转 | REV-COUNT：反转标记 <3；REV-ORDER：编号不连续 | blocker/warning |
| 钩子 | HOOK-MISSING：无钩子标记；HOOK-LATE：钩子在 30 秒后 | blocker/warning |
| 时长 | DUR-RANGE：预估时长超出 60–150 秒；DUR-TARGET：与时长目标偏差 >20% | warning |
| 人物 | CHAR-UNKNOWN：台词人名未登记；CHAR-IDLE：登记人物全集未出场 | blocker/warning |
| 台词 | DIAL-LONG：单句 >40 字；DIAL-NOACTION：整场无动作行 | warning |
| 场次 | SCENE-COUNT：场次 >6；SCENE-ORDER：编号不连续 | warning |
| 卡点 | END-HOOK：无结尾卡点；FMT：缺少标题/人物/场次任一必需段 | warning/blocker |

完整规则见 `scripts/audit/drama_audit.py` 顶部规则注册表（20+ 条）。

## 5. 人工评审清单 12 条（机器查不出的）

**钩子（3 条）**：

1. 前 3 秒有没有一个**具体动作**？（不是"他很难过"，是"他把离婚协议撕了"）
2. 这个钩子放在抖音信息流里，你自己会停下来吗？（诚实回答）
3. 钩子承诺的冲突，本集真的兑现了吗？（标题党式钩子 = 慢性自杀）

**反转（3 条）**：

4. 每个反转后，主角的处境/关系/目标有没有**实质变化**？（只反转不推进 = 无效反转）
5. 本集最强的反转，观众能不能在 5 秒内看懂？（需要解释 3 句的反转不叫反转，叫说明文）
6. 反转有没有"重复自己"？（对照反转库 8 类，本集类型不重复，近 3 集不重复用同一招）

**人物（2 条）**：

7. 反派有没有"坏得具体"？（"他很坏"✗；"他当众把女主的企划书扔进碎纸机"✓）
8. 主角的"忍"有没有边界感？（一味受辱不反击 = 观众替他着急然后划走；每集至少一次小反击）

**台词（2 条）**：

9. 有没有一句能当切片传播的**钉子句**？（没有 = 本集缺记忆点）
10. 读出声：有没有哪句台词你念了两遍才顺？（有 = 重写）

**卡点（2 条）**：

11. 结尾卡的是**动作/真相**，还是旁白废话？（"欲知后事如何" = 零分卡点）
12. 看完结尾，你最想问的问题是不是"下一集他会怎么做"？（是 = 卡点成功；只是"好奇发生什么" = 卡点偏弱）

## 6. 长叙事一致性检查（10 集以上必做）

单集自检只保证"这一集成立"，长叙事检查保证"连续看 10 集不穿帮"：

1. **人物小传对照**：每 10 集抽查一次，人物动机是否还符合最初小传（复仇的人突然恋爱脑 = 穿帮）
2. **伏笔回收表**：维护一张表（伏笔内容 / 埋下集数 / 计划回收集数 / 实际回收集数），到期未回收标红
3. **战力/财力账本**：主角展示过多少实力、花了多少钱——不能第 20 集"只剩 100 万"，第 21 集"随手买下整条街"
4. **称呼与关系冻结**：第 5 集之后，人物之间的称呼不许再变（"林先生"变"小林"只有关系升级时才允许，且需在剧本中明确写出转折点）
5. **时间线**：剧中时间流速是否自洽（"三天后"出现了 5 次，但剧情只推进了一件事 = 时间通胀）

> 与 `lhg-fiction`（长篇小说插件，规划中）的关系：两者各自实现"长叙事一致性检测"，思路互通但互不依赖；本 skill 的第 6 节即短剧版实现。

## 7. blocker 修复 cookbook：3 个最常见硬伤的改法

**例 1：REV-COUNT-001（反转不足 3 个）**

- 改前：第 5 集只有 R1（身份小露）/R2（态度反转），审计报 blocker
- 改法：加一个"信息反转"——让主角在集末发现一张旧照片，推翻之前 3 集的某个"事实"
- 改后：3 个反转，类型不重复，blocker 清零。记住：加的是"有代价"的反转，不是"他出门了"式注水

**例 2：HOOK-MISSING-001（缺少开场钩子）**

- 改前：第 8 集开场是"林凡在家吃早饭，回忆昨天"，前 30 秒零冲突
- 改法：把本集最大的冲突提前——改成"赵泰带人踹开林凡家门"，回忆压缩成一句台词带过
- 改后：钩子位于第 3 秒，blocker 清零。高潮前置永远比"娓娓道来"管用

**例 3：CHAR-UNKNOWN-001（台词人物未登记）**

- 改前：台词里冒出个"王秘书"，【人物】行没登记
- 改法二选一：① 他是重要人物 → 登记进【人物】并补一句身份交代；② 他只是传话的 → 把台词改成已登记人物说，或改成动作（"秘书递上文件"）
- 不要选"把名字改成已登记人物却不改身份"，那是新的穿帮

## 8. 反模式

- **只跑脚本不读清单**：脚本只能查结构，钩子炸不炸、钉子句狠不狠，永远是人说了算
- **warning 全豁免**：豁免是给"有理由的例外"开的口子，不是给"懒得改"开的后门；连续 3 个豁免 = 回炉重写
- **为过检而注水**：反转不够就硬凑 3 个"伪反转"（"他出门了→他回来了→他又出门了"）——审计数的是标记，观众看的是内容
- **定稿后改大纲**：剧本定稿了才发现大纲的反转排重了——顺序是"大纲先过检，再写剧本"，不要倒置

## 9. 自检与反馈

**质检门**（自检流程发布前逐项过）：

- [ ] 审计脚本在交付目录跑出零 blocker（`--fail-on blocker` exit=0）
- [ ] warning 要么修了，要么写了具体豁免理由
- [ ] 人工评审 12 条逐条有结论（通过/不通过 + 改写建议），不许跳过
- [ ] 10 集以上项目：伏笔回收表、战力账本已更新
- [ ] 豁免理由被第二人（或隔 24 小时后的自己）复核过

**标准冒烟用例**：对 `fixtures/bad` 跑审计，BAD_MUST 集合的规则必须全部命中且 exit!=0；对 `fixtures/good` 跑，零 blocker 且 exit==0。

**一键反馈**：发现规则误报/漏报，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-drama-script/issues，正文写清"剧本片段 → 哪条 rule_id 误报/漏报 → 期望行为"。
